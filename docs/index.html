One Mac, every output, tuned on its own.

UltraBass 9000 sends your system audio to as many devices as you pick, all at once. Each one gets its own volume, 5‑band EQ, filters, and delay. macOS's built-in Multi-Output Device sends the same signal to every output and can't shape or align any of them. This does both. No driver. No kernel extension.

Why no download

There's no downloadable build yet. That's on purpose: macOS only grants microphone access to signed builds. An unsigned download would launch fine and record nothing, which is worse than not shipping it at all. A signed release needs an Apple Developer ID, and that's not set up yet. Build it yourself for now. Xcode signs the app with your own developer identity when you hit Run, so the permission prompt shows up the way it's supposed to.

Features all built and working
Routing

Multi-output routing

Pick any number of outputs, and audio goes to all of them at once. No kernel extension, no separate driver.

Equalizer

Five-band EQ, per output

Three peak filters plus a low shelf and a high shelf. Drag the curve directly and the sound changes as you move it.

Filters

High-pass, low-pass, band-pass

Each one runs in series with that device's EQ, so the response curve on one output can look nothing like the next.

Delay

Delay compensation

Delay the faster devices so sound from every speaker lands at the same moment.

Auto-sync

Acoustic auto-sync

Plays a sweep through each device in turn and listens back on the built-in microphone. From that, it works out the alignment on its own. Measured on real hardware, it repeats to within ~0.2 ms.

How it works no kernel extension, no sudo
01

Tap

UltraBass 9000 copies the audio your Mac is already playing, right as it leaves each app, using a macOS process tap. Nothing gets muted. Every app keeps playing like normal.

02

Route

That copy feeds a private aggregate device, built behind the scenes and wired to whichever outputs you picked. It only exists while UltraBass 9000 is running.

03

Shape

Each output gets its own path: delay, then EQ, then filters, before the sound reaches that speaker. Every device ends up tuned on purpose, instead of playing the same signal as the rest.

FAQ straight answers, limitations included
Why do the volume keys stop working with a Multi-Output Device?+

Apple's Multi-Output Device has no single volume it can report to the system, so macOS disables the volume keys rather than guess which device you mean. With UltraBass 9000 running, the keys stay dead for a different reason: the app mutes the original playback path and keeps per-device volume as a slider inside the app instead. Capturing the volume keys to control those sliders is on the roadmap, not built yet.

Does it need a driver or kernel extension?+

No. It uses CATapDescription, added in macOS 14.2, to tap system audio in userspace, and a private Core Audio aggregate device to send that audio to the selected outputs. No kernel extension, no AudioServerPlugIn bundle, no admin installer, no restart of coreaudiod. The aggregate device exists only while the app is running.

Why is there no download?+

macOS only grants the audio-capture permission this app needs to a properly signed build. An unsigned build launches and looks like it works, but the permission prompt never appears and the tap returns silence forever, which is worse than not shipping a build at all. A signed release needs an Apple Developer ID, which this project does not have yet. Build it yourself for now; Xcode signs the app with your own developer identity when you hit Run, so the permission prompt appears correctly.

What does acoustic auto-sync measure, and what can't it measure?+

It plays a short sweep through each selected output in turn, records the result on the Mac's built-in microphone, and cross-correlates each recording against a reference to work out how many samples late or early that device arrived. From that it computes a delay per device so all of them arrive together at wherever the microphone is sitting. It is not room correction: it measures arrival time, not frequency response, and the result is anchored to one position, so moving the Mac makes the alignment stale. It cannot measure headphones or earbuds at all, since a microphone in the room can't hear audio that never left the transducer; those outputs are reported as skipped rather than given a guessed-at delay.

Does it work with Bluetooth speakers and AirPods?+

A Bluetooth speaker works like any other output: it can be EQ'd, filtered, delayed, and measured by acoustic auto-sync, since the sound leaves the speaker and reaches the microphone like anything else. Two caveats apply to any wireless device in the mix. Every output in the set syncs to the slowest one, and Bluetooth audio commonly adds 150 to 250 ms of latency on its own, which the whole system then inherits, fine for music, bad for video or games. AirPods and other earbuds or headphones are outputs a microphone can't hear, so acoustic auto-sync skips them. You can still EQ and manually delay them; automatic measurement is not available for those outputs.

Does it handle surround sound or Dolby Atmos?+

No. The process tap captures a stereo mixdown of system audio, so there is no 5.1 or Atmos passthrough. Each output device still gets its own stereo processing chain, which covers stereo speakers, a subwoofer crossed over from a stereo pair, or a Bluetooth speaker alongside built-in speakers, but not a full multichannel home-theater layout.
